# Founder launch kit

Every launch asset uses one measurable action: complete the browser walkthrough
or open a design-partner conversation. Do not imply production customers,
independent adoption, or benchmark results until first-party evidence exists.

## GitHub release body

> LIP 0.2 makes the open foodservice loyalty stack usable as an integration
> product: a deterministic ordering adapter contract and edge-case fixture
> corpus, server-side ordering BFF, member/balance migration planner,
> authenticated customer gateway, encrypted local Cloud credentials and
> recovery operations, and a browser lifecycle walkthrough. Run the
> walkthrough, then use the same evaluate-to-refund flow against the local
> reference platform. Feedback target: which source order or refund semantic
> still cannot map cleanly?

CTA: `https://opensource-loyalty.vercel.app/#walkthrough`

## LinkedIn launch post

> Loyalty APIs look simple until restaurant checkout fails between reward
> reservation, payment, and accrual—or an offline refund arrives twice. We
> built LIP as an open transaction protocol and reference platform for those
> edges. The 0.2 release adds a foodservice adapter certification corpus,
> migration reconciliation, a runnable ordering BFF, and a browser-only
> lifecycle walkthrough. No customer or performance claims: the code and tests
> are the evidence. If you own ordering or restaurant integrations, run the
> walkthrough and tell me which real edge case is missing.

CTA: walkthrough completion. Measure qualified completions and resulting
integration discussions, not impressions.
