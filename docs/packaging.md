# Packaging and commercial path

This is launch packaging, not a binding price sheet. Contract prices and service
levels require a signed order form.

| Layer | Intended user | Included | Commercial motion |
| --- | --- | --- | --- |
| Protocol | Any implementer | Spec, schemas, OpenAPI, conformance | Free, vendor-neutral |
| Reference Platform | Developer team | Engine, API, SDK, CLI, Admin, storage, Docker | Apache-2.0 self-host |
| Cloud Design Partner | Ordering platform or restaurant tech team | Managed sandbox, migration plan, adapter mapping, weekly integration review | Scoped pilot |
| Managed Cloud | Production operator | Hosted environments, upgrades, backups, monitoring, usage controls, support | Subscription |
| Enterprise | Complex operator | Dedicated topology, SSO/SCIM, data-region and contractual requirements | Custom agreement |

The first sale is a design-partner engagement, not a generic per-member plan.
The scoped output is: one source-system map, one certified lifecycle path, a
checksummed member/balance migration rehearsal, staging conformance, and a
cutover/rollback record. Usage-based packaging should be validated with real
pilots before public list prices are promised.

Self-hosters receive community support under [SUPPORT.md](../SUPPORT.md).
Commercial support must state response hours, severity definitions, recovery
ownership, exclusions, and data-processing terms in the contract.
