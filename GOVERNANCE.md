# Governance

LIP uses maintainer review with an open proposal process.

- Anyone may report bugs, improve docs, build adapters, or propose protocol
  changes.
- Maintainers merge implementation changes after tests and compatibility review.
- Normative protocol changes require a `protocol-proposal` issue, an example,
  generated schema/OpenAPI changes where applicable, conformance coverage, and
  review by two maintainers when two are active. Until then, one maintainer may
  approve but must leave the proposal open for seven calendar days.
- Security fixes may use a private process and an abbreviated public record.
- CraveUp owns Cloud pricing and operations; Cloud choices do not redefine the
  vendor-neutral protocol.

Decisions are recorded in issues and pull requests. A maintainer must disclose
a material vendor or employer conflict on a decision. Inactive maintainers can
be moved to emeritus status after 90 days without project activity and notice.
The current roster is in [MAINTAINERS.md](MAINTAINERS.md).
